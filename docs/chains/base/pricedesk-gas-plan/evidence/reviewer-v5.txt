## Must fix before implementation

**1. "Approach one", a gas check before every source call, does not fit the live Base setup.**

I read the live Base chain at block 51,532,116. The source priority order is `[1, 8, 2, 9, 4, 5]`, so Undy is second, right after Chainlink. Almost every quote Chainlink can't answer passes the Undy slot before reaching Curve, Redstone, Pyth or Stork. Checking eagerly, with Undy's budget near 3M, causes three problems:

- **Every non-Chainlink quote needs far more gas.**
  - Each one needs roughly 3.05M gas in hand just to pass Undy's slot, even though Undy answers "no feed" in a few thousand gas.
  - Robinhood clients have been seen submitting canned gas limits near 422k. If Base clients do the same, those transactions would revert.
- **Budgets cascade upward.**
  - Curve and wsuperOETHb look up their inner assets through the desk. Any inner asset Chainlink can't answer passes the Undy slot inside their envelope.
  - They would each need a budget larger than Undy's. That removes most of the benefit of per-source budgets and inflates the fault-case bound.
- **One fallback case is impossible.**
  - Under your approved fault model, take Chainlink as the faulty source. The Undy path asks the desk for USDC, Chainlink fails, and the next source in order is Undy itself.
  - The check would need more gas than Undy's own envelope contains, so it always fails.
  - All six Undy assets then lose pricing even though healthy USDC fallbacks exist at Redstone, Pyth and Stork. That contradicts the plan's own "healthy fallback is required" rule. Today's desk handles this case.

**Proposed fix: evaluate the same gas inequality only when it matters.**

- **How the check would work:**
  - Record the available gas, then make the bounded call.
  - Accept a clean answer without proof: a positive price with a feed, or zero with no feed.
  - Demand proof that the caller supplied the full budget only when the result is a failure, is malformed, or is zero with a feed.
  - If that proof is missing, revert.
- **Feed-check and snapshot calls can stay eager.** The snapshot path already skips sources with no feed.
- **Risk I checked:** a source turning gas starvation into a clean wrong answer. The two places sources swallow failures (Chainlink line 374, RedStone line 292) are admission-time `decimals()` reads, not price paths. The agent must repeat this audit on the older source builds that are live on Base.
- This is untested analysis.
- The live order and dependency read should move to the start of Stage 1, because the design depends on it.

## Medium

**8. My earlier packing advice was overstated; simplify the storage design.**
- I compiled a probe on Vyper 0.4.3. Reading one struct member costs one storage read (2,330 gas). Two members cost 4,533, and the whole struct costs 6,595.
- The quote path and the feed path each read one field. Bit-packing therefore saves about 2,100 gas, and only in the snapshot path, while adding mask and width bugs.
- I recommend a plain struct of three values with member access.
- I also recommend keeping PR #231's immutable defaults and storing only per-source overrides. That drops the default setter, the inheritance rules and one read per quote, and it keeps the existing getters.

**9. The margins stack.** Budgets get 1.5×, the transaction bound gets 1.5×, and the result must also fit 80% of the cap. A normal transaction therefore has to measure at or under roughly 8.95M gas. Large keeper batches will probably fail this gate. Confirm that stacking is what you approved.

**10. Run the paper arithmetic before any fork sweeps.** Take Undy as the faulty source at 3M per quote plus 1.5M per snapshot. A position with three Undy assets already reaches 13.5M against the 13.42M limit.

**11. The monitor threshold is too tight.**
- At exactly 1.5× headroom, usage is 66.7% on day one, so the 70% warning fires on about 5% drift.
- Use two tiers, a warning at 70% and critical at 85%, or size Undy at 2× or more.
- Under the lazy check a larger Undy budget costs nothing on healthy paths.
- The monitor should also re-check the nested-budget fit on every run.

**12. The gas-estimation test has no named tool.**

- Public Base RPCs rejected me today: PublicNode returned 403 on block-pinned calls and the official endpoint returned 429.
- The plan should name the backend, check it at the start of Stage 1, and pass `BASE_MAINNET_RPC_URL` explicitly. The existing tools load the whole `.env`, which conflicts with the no-signer rule.
